# script.md template

The script is the story. Write it before the shotlist and let it decide which screens appear.

```markdown
# <Product> - launch video script (<N> s at <BPM> BPM)

**One-line story:** <the viewer should leave thinking ...>
**Closing line (end card):** <category line>

| # | Beat | Claim on screen (<= 6 words) | What the viewer SEES (live) | Callouts (anchored to real moments) | Evidence | Tier | Length |
|---|------|------------------------------|------------------------------|-------------------------------------|----------|------|--------|
| 0 | Hook | "<Category shift>, <payoff>" | text card | - | README tagline | - | 2 s |
| 1 | Hero flow | "Search every task instantly" | types a query -> the list filters live -> a task opens | "Type to search" @typing; "Results filter live" @results | `/tasks` | 1 | 4.5 s |
| 2 | Pillar: data in | ... | ... | ... | ... | 1 | 3 s |
| 3 | Proof stat | "<N> <thing>" | counting number | - | visible in app | 2 | 2 s |
| ... |
| N | Close | "<category line>" | logo, then line | - | user/README | - | 4 s |

## Why this order
<inputs -> intelligence -> control -> outputs, or the order that builds the argument>

## Not shown, on purpose
<capability: reason>
```

Rules: one idea per scene; every "SEES" cell is a **state change** (type -> result, click -> new panel, submit ->
answer, describe -> built), not a hover; at most two hover-only scenes; every claim and number is traceable;
total 23-40 s (about 3 s per flow, 2 s per card, 4 s for the close).
